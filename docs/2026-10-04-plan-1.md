# Project Plan: UI Refresh & Feature Expansion (2026-10-04)

This plan outlines the steps to address feedback on the initial MVP: shifting to a Swiss Minimalist light/dark theme, supporting quantitative check-ins, and expanding schedule frequencies.

## Phase 1: Database & Data Model Overhaul
1. **Update `Goal` Interface**:
   - Introduce `targetUnit` (string, e.g., 'pages', 'km', 'liters') to allow task-specific quantities.
   - Expand `scheduleType` to include options like `weekdays`, `weekends`, `bi-weekly`, and `custom_days`.
2. **Update `CheckIn` Interface**:
   - Ensure the `value` field is actively used to record the quantity achieved during a check-in (rather than a simple boolean state).
3. **Migration Strategy**: 
   - Add default values for existing IndexedDB entries to avoid breaking changes, or safely clear the dev database if requested.

## Phase 2: Design System - Swiss Minimalism & Theming
1. **CSS Variables Overhaul**:
   - Implement a robust light/dark mode system using data attributes (`[data-theme="light/dark"]`) for manual toggle, falling back to system preference.
   - **Color Palette**: Move away from neon/glassmorphism. Use complementary Pantone/pastel colors (e.g., soft peach with deep slate blue, or muted sage with off-white).
   - **Typography & Layout**: Adopt Swiss design principles—heavy use of negative space, bold highly-legible typography (Inter), strict grid alignment, and flatter surfaces with high contrast text.
2. **Theme Switcher**:
   - Add a theme toggle button in the header or `Settings` component to switch between Light, Dark, and System modes.

## Phase 3: Component Refactoring
1. **Goal Creation Form**:
   - Add inputs for "Unit" (e.g., what are we counting?).
   - Update the schedule dropdown to reflect the expanded frequency options.
2. **Dashboard Check-In Flow**:
   - Modify the 1-click check-in button on the dashboard. When checking in on a quantitative goal, present an inline input or bottom-sheet to enter the achieved value for the day.
3. **Statistics Engine & Detail View**:
   - Update `stats.ts` to aggregate quantitative progress (Sum of `checkin.value`) against the `goal.targetValue`.
   - Adjust the Heatmap to potentially use color intensity based on the check-in value relative to the daily average or target.
4. **Welcome / Onboarding Page**:
   - Create a `Welcome.tsx` landing screen for new users (displayed when zero goals exist).
   - Use bold typography and generous negative space to introduce the app's core features (offline capabilities, quantitative tracking) and provide a primary CTA to create the first goal.
